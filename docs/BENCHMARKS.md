# Benchmarks

Native Rust numbers for the four solvers. The browser bench page (M3) will run the same
corpus through WebAssembly; its numbers will be added here.

## Corpus

Every puzzle is generated by this repository ([examples/corpus.rs](../crates/core/examples/corpus.rs))
and released under its MIT licence. No outside collection is used: the generator plus a
hill-climb produced puzzles hard enough to separate the solvers, so there was no licence
to check and inherit. CI regenerates all three files and fails if they differ from the
committed ones, so the corpus can't drift from the code.

| File | Puzzles | What it is |
|---|---:|---|
| [data/graded.txt](../data/graded.txt) | 500 | The first 100 puzzles of each difficulty tier among `generate::minimal_puzzle(seed)`, seeds 0 to 19,999. Minimal: every clue is necessary. 21 to 28 givens. |
| [data/hardest.txt](../data/hardest.txt) | 50 | Built to be hard for the smart solvers. Start from the 50 Beyond-tier puzzles of the sweep that cost MRV + DLX the most nodes, then hill-climb: empty a clue, add clues from the same solution until it's unique, minimise, and keep the move only if the puzzle stays Beyond and costs MRV + DLX more nodes. 200 moves per puzzle. Raised the top cost from 2,754 to 6,888 nodes. |
| [data/adversarial.txt](../data/adversarial.txt) | 20 | Built to be hard for brute force: puzzles relabelled so the solution's first row reads `987654321`, so brute force's first guess in every first-row cell is wrong. The 20 worst among seeds 0 to 499. |

**Tiers.** A puzzle's tier is the hardest technique an easiest-first human-style solve
needs ([human.rs](../crates/core/src/human.rs)): Easy (singles), Medium (pointing,
box-line reduction), Hard (naked and hidden pairs, X-Wing), Expert (triples, Swordfish,
XY-Wing), Beyond (needs more than these: chains or guessing). Share among the 20,000
swept minimal puzzles: Easy 41.5%, Medium 11.9%, Hard 6.5%, Expert 4.9%, Beyond 35.1%.

## Method

- `cargo bench` runs [crates/core/benches/solvers.rs](../crates/core/benches/solvers.rs):
  every solver on every puzzle, stopping at the first solution, no trace. Tiers are
  computed by the bench, not read from the file's comments.
- A puzzle's time is the fastest of 3 to 5 runs. Median and p95 are nearest-rank over
  the puzzles. Nodes, backtracks and checks are means over the puzzles. Brute force and
  bitmask stop at 100 million nodes and count as aborted; none did.
- The machine is a laptop with a hybrid CPU, so the bench is pinned to logical CPU 0 (a
  performance core) at high priority. Unpinned runs on this machine were up to 7× slower
  for the same work when Windows put the thread on an efficiency core. Absolute times
  also drift a few tens of percent as the laptop heats up, so compare builds only within
  one session.

```sh
powershell -File scripts/bench.ps1 > bench.md   # builds, then runs the bench pinned to CPU 0
```

## What the numbers say

- **Human difficulty is not machine difficulty.** From Easy to Beyond, MRV's mean nodes
  only go from 56 to 102, and brute force has no trend at all (its Easy tier is its
  costliest). A person is slowed by needing a rarer pattern; a search is slowed by
  guesses that propagate badly, and by digit order for brute force. Grading by technique
  is right for players; benchmarking needs sets built against the solvers, which is why
  hardest.txt and adversarial.txt exist.
- **Bitmask vs brute force: same tree, cheaper checks.** Node and backtrack counts are
  identical (a test asserts it); one mask operation per cell replaces nine 27-cell scans.
  5.5 to 7.7× faster at the median in every set.
- **MRV + propagation: a smaller tree.** 56 to 102 nodes against 57,000 to 165,000 for
  brute force on the graded tiers, because naked and hidden singles settle most cells
  without guessing and the branch is taken where the fewest candidates remain. Two to
  three orders of magnitude faster.
- **Digit order is brute force's weakness, not the others'.** On adversarial.txt brute
  force's median is 66 to 97× its graded medians; MRV and DLX don't change.
- **On the hardest puzzles DLX nearly catches MRV.** On the graded tiers DLX takes 1.7
  to 3.6× MRV's median: its per-node pointer work costs more while propagation settles
  most cells for free. On hardest.txt, where both must search (89 backtracks), DLX is
  1.6× MRV's median, 1.2× its p95, and equal at the max. DLX is the general exact-cover
  algorithm: the same code solves pentominoes or N-queens once the columns change.
  Sudoku-specific propagation beats it on easy ground and the gap closes as the search
  gets real.

## DLX tuning (2026-11-12)

An earlier version of this page blamed DLX's gap on scanning about 200 columns per node.
The counters disproved it: 2,841 checks over 74 nodes is about 38 column reads per node,
because the scan already stopped at a column of size 1. A timing probe over 200 puzzles
(mean, pinned) then split DLX's time: **building the matrix took about 37 µs of 92 µs**,
40%, while MRV took 83 µs in total.

Two changes, measured in the same session to cancel the laptop's thermal drift:

1. **Early exit on the first column too.** The scan stopped at size 0 or 1 only when that
   column was strictly smaller than the current best, so a size-0 or size-1 first column
   was missed. Mean checks fell from 2,841 to 2,036 (-28%). Nodes moved from 74 to 77
   because ties now resolve to an earlier column.
2. **One array of node structs** instead of six parallel arrays (left, right, up, down,
   column, candidate): one allocation sized to the rows actually needed, and cover and
   uncover read one node's links from one cache line. Setup fell from about 30 µs to
   about 20 µs in the probe.

DLX median as a multiple of MRV median, alternating old and new builds back to back
(`scripts/bench.ps1`) on the M1 corpus (`minimal_puzzle(0..500)`, since replaced by
graded.txt) and adversarial.txt:

| Corpus | Before (run 1, run 3) | After (run 2, run 4) |
|---|---|---|
| minimal_puzzle(0..500) | 2.85×, 2.68× | 2.44×, 1.94× |
| adversarial.txt | 3.06×, 3.19× | 2.06×, 2.77× |

About a quarter less time relative to MRV. MRV still wins on these puzzles: its
propagation settles most cells before any branch.
