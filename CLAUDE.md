# GridRace

Sudoku solver, generator and solver race: four instrumented solvers (brute force,
bitmask, MRV + propagation, Dancing Links) in Rust, compiled to WebAssembly and run in a
Web Worker; a React + TypeScript + Vite + Tailwind front end; a static site on Cloudflare
Pages at gridrace.dhruvgoyal.tech. No backend.

This file is the project's constitution. It binds every change, human or AI. To weaken
a rule, change this file in its own commit and say why.

| Milestone | Scope | State |
|---|---|---|
| M1 | Rust core: four solvers, counters, traces, generator, tests, fuzzing, benchmarks | done |
| M2 | Human-style solver, hints that explain why, difficulty grading | next |
| M3 | Web app: DESIGN.md first, play, race with replay, hints, generator, paste | |
| M4 | PWA, SEO, Lighthouse, Cloudflare Pages, e2e on the live site | |

## How we work

- **Verify, never guess.** Every version, API and claim is checked against an official
  doc, a registry or a run. A number in a doc comes from a command someone can rerun.
- **Direct to main, one commit per logical piece.** No branches, no pull requests.
  `bash scripts/gate.sh` passes before every commit. Then push. If CI goes red, the next
  commit fixes it. Never force-push main.
- **Identity.** Every commit is authored and committed by the owner only, set in the
  repo's local git config. No co-author trailer, no generated-by line, and no mention of
  any AI tool in a commit message, tag, release or other GitHub-visible metadata.
  Attribution is off in the git-ignored `.claude/settings.local.json`. After each commit,
  `git log -1 --format='%an <%ae> | %cn <%ce>%n%B'` must show only the owner. If that
  can't be guaranteed, don't commit: give the owner the commands.
- **A red gate stops the line.** No `--no-verify`, no disabling a test to get green.
- **Say what's unfinished.** Open risks stay visible in the doc that owns them.

## Dependencies

- **14-day rule.** Adopt only a release published at least 14 days ago (crates, npm, the
  Rust toolchain, dated nightlies, GitHub Actions). If the newest is younger, take the
  newest that is older. `scripts/check-deps.mjs` enforces it for lockfiles and toolchains.
- **Exact pins.** Crates as `=x.y.z`, npm without `^` or `~`. Lockfiles committed.
  `--locked` / `npm ci` in CI. A too-new transitive crate is held back with
  `cargo update -p <crate> --precise <version>` (fuzz/: `cc` at 1.10.0).
- **Clean audits.** `cargo deny check` (advisories, licences, sources) and `npm audit`.
- **Security exception:** a fix for a published advisory may be younger than 14 days.
  Record it in docs/DEPENDENCY_EXCEPTIONS.md with the advisory, the date and an expiry.
- **The solver core has no dependencies.** Keep it that way; add one only if the
  alternative is clearly worse.
- Actions pinned by commit SHA, images by digest (`scripts/check-workflows.mjs`).

## Solver invariants (never weaken without explicit approval)

- Counters mean the same in every solver (definitions in `crates/core/src/search.rs`):
  nodes = placements tried (guessed or forced), backtracks = guesses undone,
  checks = legality queries. Brute force and bitmask visit identical trees; a test
  asserts it.
- Traces record placements and undos only, stop at the caller's cap, and say when they
  were capped. Never send an unbounded trace across the WASM boundary.
- Every search honours `node_limit` and reports `aborted`; the browser always sets one.
- The core never uses `std::time`, threads or I/O: it must build for
  `wasm32-unknown-unknown` (CI checks). Callers time the solve.
- Givens are validated before any search; conflicts are returned, never panicked on.
  Nothing reachable from untrusted input panics (the fuzzer checks).
- A generated puzzle has exactly one solution (counted to 2), and difficulty is graded
  by the hardest technique needed, not by the number of empty cells.
- The benchmark corpus is generated by this repo (`examples/corpus.rs`, MIT) and CI
  checks it matches the committed `data/`. No third-party puzzle set without a recorded
  licence.

## Testing and CI

- CI (`.github/workflows/ci.yml`): policy scripts, gitleaks, fmt, clippy pedantic
  `-D warnings`, tests, wasm32 build, bench compile, corpus check, cargo-deny, and
  2 minutes of fuzzing on nightly-2026-10-28.
- Property tests use the crate's own seeded PRNG: a failure prints a seed that
  reproduces it.
- Piped CI steps use `set -o pipefail`.
- `exceptions.yml` runs the dependency check daily. GitHub disables scheduled
  workflows after 60 days without activity: check `gh workflow list` after a quiet spell.

## Deployment

Static files on Cloudflare Pages (free tier). Nothing bills while idle, so there are no
up/down scripts; the README says so. Strict CSP, no third-party scripts at runtime.

## Environment

Windows 11, Git Bash. Rust through rustup (`~/.cargo/bin`, not on the default PATH of
every shell: `export PATH="$HOME/.cargo/bin:$PATH"`). Node through nvm-windows
(`.nvmrc`). MSVC Build Tools for the native target.

- rust-analyzer can lock files under `target/debug/incremental`; the gate sets
  `CARGO_INCREMENTAL=0`.
- The laptop CPU is hybrid (P and E cores): benchmark numbers come only from `scripts/bench.ps1`, which pins
  the run to CPU 0 at high priority. Compare builds only within one session (thermal drift).
